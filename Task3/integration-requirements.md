# Требования к внешним интеграциям: «Умный дом»

Интеграция партнёрской платформы с PropDevelopment через мобильное приложение собственников.

## Организация взаимодействия между системами

### Участники

- Мобильное приложение собственников — UI: домофон, шлагбаум, настройка доступа
- tenant-core-app — маршрутизация запросов из приложения
- smart-home-service — сценарии домофона и шлагбаума, правила доступа
- integration-gateway — единая точка вызовов к партнёру, webhooks, контроль доступа по ЖК
- Платформа партнёра «Умный дом» — видеодомофон, биометрия, распознавание номеров, устройства

### Схема взаимодействия

- Собственник → приложение → tenant-core-app → smart-home-service → integration-gateway → платформа партнёра
- События от партнёра (звонок, распознавание) → integration-gateway → smart-home-service → push в приложение
- Прямых вызовов к партнёру из tenant-core-app нет — только через gateway

### Домофон

- Собственник задаёт список лиц с доступом в smart-home-service
- Правила уходят партнёру через gateway; биометрия хранится у партнёра
- При звонке или распознавании партнёр шлёт webhook; собственник может открыть дверь из приложения
- Автооткрытие — только для лиц из белого списка

### Шлагбаум

- Собственник привязывает госномера к профилю и ЖК
- smart-home-service синхронизирует белый список с партнёром
- При распознавании номера партнёр открывает шлагбаум или ждёт подтверждения
- Ручное открытие — из приложения

### Принципы

- PropDevelopment не хранит биометрию и видеопотоки — только ID и правила
- Доступ изолирован по ЖК и квартире
- Контракт API согласуется со специалистом ИБ до production

## Протоколы аутентификации и авторизации

### Собственник → PropDevelopment

- OAuth 2.0 / OpenID Connect через auth-service-1 (Keycloak)
- Authorization Code + PKCE для мобильного приложения
- JWT (access + refresh), срок access token — не более 15 минут
- Авторизация: роль «собственник» + привязка к owner_id, apartment_id, residential_complex_id

### PropDevelopment → платформа партнёра

- HTTPS (TLS 1.2+)
- OAuth 2.0 Client Credentials + mTLS
- Авторизация по scope: intercom, barrier, access
- В каждом запросе заголовок X-Tenant-Id (ID ЖК)

### Платформа партнёра → PropDevelopment (webhooks)

- HTTPS POST, JSON
- Аутентификация: HMAC-SHA256 или JWT (RS256)
- IP allowlist партнёра, проверка подписи в gateway
- Idempotency-Key для повторных доставок

### Внутри PropDevelopment

- Приложение → tenant-core-app: REST + JWT Bearer
- tenant-core-app → smart-home-service: REST + service JWT
- smart-home-service → integration-gateway: REST + service account

## Требования к безопасности

### Общие

- Только TLS 1.2+, запрет HTTP
- Секреты партнёра — в secrets-vault, не в коде и конфигах
- Журналирование всех операций: кто, когда, устройство, действие
- Rate limiting на gateway и webhook-endpoint
- Согласование API с ИБ; не передавать лишние ПДн
- Tenant isolation: партнёр одного ЖК не видит данные другого

### Персональные и биометрические данные (152-ФЗ)

- Биометрические шаблоны — только у партнёра; у PropDevelopment — ID и статус согласия
- Отдельное согласие на биометрию до регистрации лица
- Видеопоток не хранится в PropDevelopment; просмотр — через signed URL партнёра
- Срок хранения логов — по политике и закону
- Удаление биометрии и данных авто — каскадный запрос к партнёру через API

### Домофон

- Ручное открытие — только аутентифицированный собственник; MFA для критичных ЖК
- Автооткрытие — только белый список собственника
- Журнал: звонок, распознавание, открытие, timestamp
- Push без биометрии — только ЖК, подъезд, время

### Шлагбаум

- Госномера привязаны к owner_id и residential_complex_id
- Автооткрытие — при confidence не ниже согласованного порога
- Ручное открытие — с подтверждением в приложении, с логированием
- Гостевой доступ — с TTL, минимум ПДн для партнёра

### Надёжность

- Таймаут вызова партнёра — не более 5 сек; circuit breaker
- Очередь повторной доставки webhooks
- Алерты при массовом открытии, ошибках авторизации, сбое синхронизации
- SLA партнёра: доступность API не ниже 99,5%
